The records database

The database is the one the site itself answers from: one SQLite file holding every election, contest, candidacy and count, the people and parties linked to them, offices, parliamentary divisions and votes, registers of members' interests, the map catalogue, the source catalogue with its citations, and the linked-data graph. When it was measured on 9 November 2026 it held 21,010 contests, 76,994 candidacies, 44,690 citations, 1,339 map layers and 307,826 graph entities.

Unzip it and open it with any SQLite tool, for example sqlite3 civgraph-records-latest.sqlite or DB Browser for SQLite. The dataset table holds its version. Each record cites its source in the citations and provenance tables.

OWNER: decide whether to publish a short schema guide (table by table) with the downloads. The schema is in packages/schema/migrations/ in the repository.

The graph

Civgraph links people, places, elections, offices and sources into a graph of entities and statements. The graph archive holds it in JSON-LD and RDF, with provenance for each statement. The three small .gz files list what the archive holds.

OWNER: the JSON-LD uses identifiers under https://civgraph.org/id/, which do not resolve (the launch QA, item M11). Either redirect them to civgraph.net or move the identifiers to civgraph.net before this page invites linked-data use.

Versions and checksums

Each release of the records database has a version, a short code that also appears in its file name. A versioned file never changes once published; -latest always points to the newest. Check a download against the SHA-256 in the manifest, for example with sha256sum on Linux, shasum -a 256 on macOS or certutil -hashfile <file> SHA256 on Windows.

To cite a release, see How to cite.

OWNER: confirm a versioned file is never overwritten (the version comes from the database's dataset table; nothing in the upload stops a rebuild reusing it). Decide how long older versioned files stay downloadable (only the newest is on R2 today), and whether to deposit releases with Zenodo for a DOI.

API

Civgraph's records can also be queried one at a time through a read-only JSON API at https://civgraph.net/api/v1. The index lists every endpoint and its parameters, and /api/v1/openapi.json describes them in OpenAPI 3.1. It answers GET and HEAD. Endpoints cover elections, people, parties, sources and citations, registers of interests, parliamentary votes, the graph, headline counts, the map catalogue and layers, map feature search, and the PRONI eCatalogue.

Version 1 changes only by adding things: parameters, fields and endpoints may be added, but none is removed or changed in meaning. An incompatible change would be a new version, and v1 would keep answering.

For anything more than a few thousand requests, please use the downloads instead.

OWNER: confirm whether there are rate limits to state, and whether the PRONI endpoints (including CSV export) should be advertised.
