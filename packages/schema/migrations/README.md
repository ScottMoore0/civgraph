# Records database migrations

The schema of the records database (D1 `civgraph-elections`, binding `ELECTIONS_DB`), as
append-only SQL files applied in name order. `wrangler.toml` points `migrations_dir` here.

- Locally: `npx wrangler d1 migrations apply civgraph-elections --local --persist-to .wrangler/state`
  (`npm run records:deploy -- --local` runs it before each load).
- Remotely: `--remote`, and only inside a publish the owner has approved.
- Never edit a file that has been applied anywhere. A change is a new file (`0002_...sql`),
  made together with the matching change to `packages/schema/src/schema.mjs`, which is the one
  table list the loader, the delta, verify and the tests read.
- `0001_records.sql` was generated by `node packages/schema/src/schema.mjs --sql`;
  `tests/records/schema.test.mjs` holds the applied migrations equal to `schema.mjs`.

`0001` creates the phase-2 tables beside the live ones and touches none of them. Two names
collide with live tables of another shape, so they are created as `r_elections` and
`r_counts`; stage H's migration drops the legacy tables and renames these two in the same
publish as the Function change that flips `T.elections` and `T.counts` in
`packages/api/src/handlers/_records.js`.
